## Итерация 0. Подготовка и инфраструктура (2 недели)

**Цель:** настроить окружение, выбрать инструменты, создать базовую структуру.


- Настроить простой CI/CD (например, GitHub Actions) для автоматической сборки и деплоя на тестовый сервер (пока можно использовать VPS без Kubernetes, достаточно docker-compose в продакшене на первом этапе, чтобы не усложнять).
- Спроектировать схему БД (только основные таблицы: users, polls, questions, options, votes). Остальное добавим позже.
- Определить структуру Go-проекта: можно начать с монолита внутри `micro` (один сервис с несколькими handlers), чтобы не тратить время на межсервисное взаимодействие. Позже, при необходимости, выделим микросервисы.

## Итерация 1. MVP – базовая аутентификация и простые опросы (6 недель)

**Функционал:**
- Регистрация по email + пароль, вход, выход (JWT). Подтверждение email пока можно пропустить (сделать опционально, но лучше сразу добавить отправку письма через простой SMTP без очереди – синхронно).
- Создание опроса с **одним типом вопроса** (одиночный выбор) – без медиа, без гео, без привязки к дате окончания.
- Опрос может быть **публичным** (доступен всем) или **по ссылке** (только знающим URL). По умолчанию разрешено голосовать без авторизации.
- Страница опроса: отображение вопроса и вариантов, голосование (для авторизованных – привязка к user_id, для неавторизованных – сохранение с ip и session_id в куках для предотвращения повторных голосов на уровне сессии).
- После голосования показывать **простую статистику** (количество голосов за каждый вариант, проценты) – без графиков.
- Личный кабинет пользователя: список созданных им опросов, возможность удалить опрос.
- Главная страница – статичный лендинг с описанием (пока без динамики).

**Технические решения для одного разработчика:**
- Бэкенд: монолит на Go с фреймворком `micro` (используем только REST, gRPC не нужен на старте). Одна кодовая база.
- Фронтенд: Angular с минимальным дизайном (можно использовать готовую библиотеку компонентов, например Angular Material).
- База: PostgreSQL, для кэша – Redis (пока только для сессий и хранения JWT).
- Очереди не используем (отправка писем синхронно или через отдельную горутину).

**Оценка времени:**
- Настройка auth (регистрация, логин, JWT) – 1 неделя.
- CRUD опросов (создание, список, получение, удаление) – 1,5 недели.
- Страница голосования (фронт + бэк) – 1,5 недели.
- Статистика (подсчёт голосов) – 1 неделя.
- Личный кабинет, главная, вёрстка – 1 неделя.
- Итого: 6 недель (с учётом неизбежных багов и доработок).

**Результат:** рабочий прототип, на котором можно создавать опросы и голосовать. Можно запустить для тестирования.

## Итерация 2. Расширение функционала (4 недели)

**Добавляем:**
- Подтверждение email (через ссылку) и восстановление пароля.
- Редактирование опроса (до первого голоса) и завершение опроса досрочно.
- Типы вопросов: множественный выбор, шкала (1–5), текстовый ответ.
- Настройка видимости результатов (сразу или после завершения).
- Автоматическое закрытие по дате.
- Кэширование опросов в Redis (для ускорения загрузки публичных страниц).
- Простая защита от повторных голосов для неавторизованных (через куку + IP).

**Оценка:** 4 недели.

## Важные рекомендации для одного разработчика

1. **Не усложняйте архитектуру** – начните с монолита. Вы всегда сможете выделить микросервисы позже, если нагрузка вырастет.
2. **Используйте готовые библиотеки и фреймворки** – не изобретайте велосипеды (например, для аутентификации можно взять `go-chi/jwt` или `golang-jwt`, для валидации – `go-playground/validator`).
3. **Сосредоточьтесь на качестве кода и тестировании** – это сэкономит время на отладке.
4. **Деплойте на ранних этапах** – используйте VPS с docker-compose для быстрого развёртывания. Kubernetes можно отложить до момента, когда понадобится масштабирование.
5. **Автоматизируйте рутину** – CI/CD, миграции БД, бэкапы.
